# On-Page Editor (OPE)

A capability you attach to a page you already have. Drop `ope.js` and `serve.py` beside the HTML,
add one `<script>` tag, open the page through the bundled server. An **Edit Mode** pill appears in
the corner: click it, drag blocks to new positions, rewrite wording inline, save. The HTML file on
disk is the single source of truth and the only thing written.

OPE is not an application. No database, no accounts, no admin panel, no config format, no plugin
ecosystem, no build, no dependencies. Delete the two files and the page is exactly as it was.

## Use this when

- A static page or a hand-written artifact needs layout or copy changes, and the person making them
  will not run a build, a CMS, or a developer loop.
- The page already exists as a file on disk that you are allowed to overwrite.
- You want the change history in plain text next to the page (`changes.md`), not in a database.

## Do not use this when

- The page is generated by a framework or a build step; edits would be overwritten on the next build.
- The page needs multi-user review, permissions, or workflow. There are no accounts and no auth.
- The directory you would serve holds anything private. See the exposure note below.

## Install

Two files, copied next to the page:

```bash
# from a clone of the project
cp ope.js serve.py /path/to/your/site/
cd /path/to/your/site
python3 serve.py            # defaults to 127.0.0.1:8899
```

Open `http://127.0.0.1:8899/<page>.html`. Add the script tag just before `</body>`:

```html
<script src="ope.js"></script>
```

Python 3.9+ standard library only; no pip install, no npm install.

## Configure (per page, before the script tag)

```html
<script>
  window.OPE_CONFIG = {
    page: 'index.html',                 // filename the save posts back to
    draggable: ['.card', '.panel'],     // blocks that may be reordered
    editable: ['.title', '.body'],      // text blocks that may be rewritten inline
    svg: true                           // enable dragging SVG groups carrying [data-mi]
  };
</script>
```

Selectors are what the human is allowed to touch. Anything not listed stays fixed, which is how you
keep a page's structure honest while still letting its owner rearrange it.

## How a save works

`POST /save?file=<page>` with a JSON body `{html, ope_ver, changes, page}`:

- The path must resolve inside the served directory, checked on a path-component boundary, so a
  sibling directory whose name merely prefixes the served one cannot be written to.
- Only `.html` / `.htm` targets are writable.
- A tab carrying a stale `ope_ver` is rejected with **HTTP 409** rather than overwriting newer edits.
- The current file is copied to `<page>.bak` before the write.
- An entry is appended to `changes.md`: what moved, what text changed, before and after.
- `OPE_NOTIFY_DIR` (optional environment variable) drops a JSON notification after each save.

## Security model, stated plainly

- Binds `127.0.0.1` by default. Passing a host (or setting `OPE_HOST`) exposes it; that is opt-in.
- `POST /save` requires `Content-Type: application/json`. A cross-origin `text/plain` form post is a
  CORS "simple request" that skips the preflight; requiring JSON forces a preflight, which this
  server never answers, so a third-party page cannot rewrite your files.
- Requests declaring `Sec-Fetch-Site: cross-site` are rejected.
- The body is bounded (32 MB) and each connection has a socket timeout, so an unbounded read cannot
  park a handler thread indefinitely.
- **Exposure note:** everything in the served directory is readable by anyone who can reach the
  port, including `<page>.bak` and `changes.md`. Serve a directory that holds only publishable
  files. `changes.md` accumulates the human's edited wording.

## Pitfalls

- **Stale cache after save.** HTML pages and `ope.js` are served `Cache-Control: no-cache` on
  purpose. Without it, a same-second mtime makes a reload return 304 and show the old content,
  which reads as "the save silently failed". Do not add caching in front of this server.
- **Two servers on one directory.** Concurrent editors overwrite each other's `html` payload; the
  409 guard only protects against a stale tab, not against two people.
- **`.bak` is one deep.** Each save overwrites the previous `.bak`; it is a safety net for the last
  edit, not a version control system. Keep the page in git if you want history.
- **Do not narrow `draggable` / `editable` with IDs that the page regenerates.** Use stable classes.

## Verify it works

1. Load the page through `serve.py`; the Edit Mode pill is visible in the corner.
2. Enter edit mode, move one block and change one word, save.
3. `git diff` (or `diff` against your copy) shows exactly those two changes; `<page>.bak` holds the
   previous bytes; `changes.md` gained one entry.

## Files

- `ope.js`: the shared editing engine, injects the toolbar, view toggle and CSS.
- `serve.py`: static server plus the guarded `/save` endpoint.
- `demo.html`: a page that exercises every editable surface.
